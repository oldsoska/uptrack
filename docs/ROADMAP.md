# Roadmap

## MVP
- [x] Мониторы: CRUD через REST API, пауза, валидация в коде и CHECK-ограничениями в БД
- [x] Планировщик: горутина на монитор, семафор на одновременные проверки, разнос первого запуска
- [x] Проверка HTTP: таймаут, диапазон ожидаемых кодов, редиректы, защита от SSRF
- [x] Машина состояний UP/DOWN с порогом неудач, инциденты (один открытый на монитор — гарантия БД)
- [x] Алерты: Telegram, webhook, повторы с экспоненциальной задержкой
- [x] Статистика: аптайм, p50/p95, полоски за 30 дней; публичная страница статуса
- [x] Prometheus-метрики, health/readiness, JSON-логи (slog), graceful shutdown
- [x] Тесты: юнит, `-race`, интеграционные на PostgreSQL (Testcontainers); govulncheck в CI
- [x] Docker (distroless, non-root), docker-compose, GitHub Actions
- [ ] Деплой и мониторинг живого стенда Slotly

## Надёжность
- [ ] Transactional outbox для алертов: событие пишется в той же транзакции, отправка — отдельным воркером
- [ ] Выбор лидера через `pg_try_advisory_lock`: проверки выполняет один экземпляр из нескольких
- [ ] Партиционирование `check_results` по дням вместо DELETE по возрасту

## Возможности
- [ ] Проверка содержимого ответа (подстрока / JSON-путь), проверка срока SSL-сертификата
- [ ] Проверки из нескольких регионов, «упал» только при согласии большинства
- [ ] Окна обслуживания: не алертить в запланированное время
- [ ] Несколько пользователей и API-ключи вместо одного токена администратора
- [ ] Grafana-дашборд в репозитории
